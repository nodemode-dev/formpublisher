# Releasing

A release has two halves. This repository moves the version and passes its checks. FormCompiler, the family's build repository, builds, signs and drafts the desktop app. Nothing here builds a release.

## The version

Versions are `X.Y.Z`. The repository started at 0.0.0 (the foundations), and the first release was 0.1.0. The family's rule, which FormCompiler's gate enforces: `Z` runs 0 to 9 and `Y` 0 to 99, with no zero padding. The fix after 0.15.9 is 0.16.0, never 0.15.10. A release must be above the highest version already published.

## The 17 version sites

Raise the version by hand in all 17 sites, in one commit:

1. `.claude/skills/formpublisher-harness/SKILL.md`
2. `.claude/skills/formpublisher-skillset/SKILL.md`
3. `.agents/skills/formpublisher-harness/SKILL.md`
4. `.agents/skills/formpublisher-skillset/SKILL.md`
5. `.docs/wiki/Home.md`, the Release version line
6. `README.md`, the version badge (the alt text and the address, on one line)
7. `backend/app/__init__.py`
8. `docs/MANUAL.md`, the first `builtWith` example
9. `docs/MANUAL.md`, the second `builtWith` example
10. `frontend/package.json`
11. `frontend/package-lock.json`, the top `version` field
12. `frontend/package-lock.json`, the `version` field of the root package
13. `frontend/src/version.ts`
14. `src-tauri/Cargo.toml`
15. `src-tauri/Cargo.lock`, the `formpublisher` package
16. `src-tauri/tauri.conf.json`, the site FormCompiler reads
17. `src-tauri/HASHOUT_LOG.md`, the header (Current build version and Last updated)

`CHANGELOG.md` has the version's entry before the release commit. The demo's data (`demo/data/`) names the version too, but it is generated by the demo's tools, not edited by hand.

## The checks before the release commit

Run these with the new version in place. All must pass:

| Check | Run |
| --- | --- |
| Skills, the MCP tool list and the stated counts | `./formpublisher agents sync --check` (it must say "in step") |
| The interface type check and build | `npm run build` in `frontend/` |
| The engine tests | `python -m pytest -q backend/tests` |
| Every language is complete | `python setup/i18n_check.py` |
| The Python locks hold every pin | `python setup/lock_requirements.py --check` |
| The shell type check | `cargo check --locked` in `src-tauri/` (it needs `frontend/dist`) |

CI (`ci.yml`) runs the same on every push to main, and FormCompiler builds only a commit whose checks passed.
## The release commit

The release commit is `chore(release): X.Y.Z`. It is the last commit on its pull request, and it holds the 17 version sites. Commits have one author and committer, `nodemode-ai <mackin@nodemode.ai>`, and no trailers. Work reaches main through a pull request.

## The build, in FormCompiler

Building the desktop app happens in FormCompiler, not here. After the pull request has merged, the maintainer runs `formai-build`. It offers each registered app at the version it finds on main, and after the maintainer confirms, it makes the `compile_vX.Y.Z` branch at main's commit and starts the release. An assistant has no `compile_v` step: it never creates, moves or pushes such a branch, and never starts FormCompiler's release workflow.

FormCompiler reads this app from its registry entry, `apps/formpublisher.json`:

- The version comes from `src-tauri/tauri.conf.json` at the commit, and it must be the one the branch names.
- `ci.yml` must have passed on that commit.
- The platforms are macOS on Apple silicon and Intel, Linux x64 and Windows x64.
- The build runs this repository's own scripts: `./formpublisher install` and `./build_app` on macOS and Linux, `build_app.bat` on Windows. `./build_app` freezes the engine with `setup/freeze_backend`, whose self-check must pass, and builds the Tauri shell around it.
- Signing keys live in FormCompiler. This repository holds none.
- The result is a draft release `vX.Y.Z` on this repository, with the installers, `SHA256SUMS.txt`, `form-app.json` and the skills archive made from `.claude/skills`. A maintainer publishes the draft.

To try a desktop build on your own computer, run `./build_app`. That is a local build, not a release.

## Rules that stay
- Every shipped dependency has its row in `NOTICE.md`.
- FormPublisher is GPL-3.0-only. Permissive and GPL-3.0-compatible licences are fine, AGPL is used nowhere, and LGPL code ships only as a separate program.
- A published release is never overwritten. A fix is a new version.
