# Checks

Checks produce problems with a stable id (a deep problem's id does not depend on the host's port, so it is the same on every run), a tier (`static`, `live`, `deep`), a severity (`error`, `warning`, `info`), a code, a route, a message and a fix. The Problems tab lists them, filters by severity and tier, and selects the route of a clicked row.

## Static

Runs offline on the revision's files. Codes: `link.broken`, `link.anchor`, `asset.missing`, `redirect.loop`, `redirect.chain`, `redirect.target`, `sitemap.missing`, `sitemap.extra`, `robots.sitemap`, `robots.blocks`, `meta.title`, `meta.description`, `meta.lang`, `img.size`, `img.alt`, `heading.h1`, `heading.order`, `external.request`, `forms.local-address`, `budget.file`, `budget.page`, `seo.canonical`, `seo.og` (info), `seo.jsonld` (error), `seo.hreflang`, `site.favicon`, `site.404`, `a11y.link-name` and `a11y.label`. `seo.canonical` is a warning for a missing canonical link on a page that is not `noindex`, more than one, or one that is not a full address. `seo.og` names the missing tags among `og:title`, `og:type`, `og:image` and `og:url`, once per page, and an `og:image` that is not a full address; it is info because FormWeb exports no `og:image` today. `seo.jsonld` is an error for a JSON-LD block that does not parse, and nothing when there is none. `seo.hreflang` warns on an invalid code, an address that is not full, a page that does not list itself, a self entry in another language than the route's locale, and a missing return link, once on the page that lacks it. `site.favicon` and `site.404` warn once per site: no `rel=icon` on the home page and no `/favicon.ico`; neither `404.html` nor `404/index.html`. `a11y.link-name` warns on a link with no name a screen reader can announce, `a11y.label` on a form field with no label. `forms.local-address` is a warning for a form that posts to this computer, the local network or FormWeb's `/api/forms/` route, none of which answers once the site is published. `external.request` is one warning per distinct remote URL, with the number of references and the pages that use it. Each code's rule and severity is a table in the manual.

## Live

From the preview probe: console errors, page errors and failed requests are errors; console warnings are warnings; layout shift of 0.001 or more is a warning and 0.1 or more an error; overflow is an error. A shift within 500 ms of the preview frame changing size, or before the page's first paint, is the preview's doing and is not counted. Live problems reach the engine at most once a second.

## Deep

Serves the revision through the same site host as the preview and drives the Chrome or Microsoft Edge you already have installed with Playwright, at 1440 and 390 wide, with a 4x CPU slowdown and a slow network. It runs in the desktop app too: Playwright and its Node.js driver are frozen into the engine. Codes: `deep.console`, `deep.pageerror`, `deep.request`, `deep.external`, `deep.cls`, `deep.overflow`, `deep.unavailable` (info) when no browser can be started (from source, also when Playwright is missing; in the installed app its fix says to install Chrome or Edge or set the browser's path, and its row has an Open Preferences button that opens Preferences at Checks, where the browser is set), and `deep.failed` (error) when the run fails for another reason. A run that fails sends the live event `checks.failed` (`run`, `site`, `revision`, `tier`, `reason`) instead of `checks.done`, is logged, and shows one Problems row, "The deep check could not finish: [reason]". It saves a thumbnail per route under `checks/[site]/[revision]/thumbs/`. FormPublisher never downloads a browser; from source the requirements are in `backend/requirements-deep.txt`, which the lock includes.

On every route and width the deep run also measures speed and contrast. `deep.lcp` is the largest contentful paint, read one second after load and before the run scrolls: a warning over 2.5 s and an error over 4 s. `deep.cls` is a warning for any layout shift and an error at 0.1 or more. `a11y.contrast` warns when text is below WCAG 2.2's 4.5:1 (3:1 for large text, 24 px or 18.66 px bold), naming the worst three; up to 400 text elements a page are read, and a failure is reported only when it holds after 400 ms and 150 ms. Contrast over images, gradients, blending, filters, painted pseudo-elements, other elements or moving content is counted as not measured, never guessed. `deep.skipped` (info) says that one of the two measurements failed on a page and the rest went on. These are lab values from this computer with the CPU and network slowed, not visitors' values; INP needs a real visitor and is not measured.

The report carries `measures`, one per route and width (`route`, `width`, `lcp` in seconds, `cls`, `lcpElement`, `contrast` counts, `notes`), and `inp: "not measured"`. The window shows them as a Speed block at the end of the Problems list (with All tiers or Deep in the filter): one row per route, LCP and CLS for each width, a warning or error icon named Warning or Error past the limits, and the lab-value line under it. Without a deep run the block is absent. `run_checks`, `get_checks` and `check --deep` return or print the same values.

Prepare warns for Cloudflare Pages past 100 header rules in `_headers` or a line over 2,000 characters, as it does past 2,000 static and 100 splat redirects.

Each rule's source (Google Search Central, ogp.me, MDN and the HTML standard, the hosts' 404 documentation, WCAG 2.2, web.dev and Cloudflare Pages' Headers page) is linked from the manual's "Where the rules come from".

## Storing results

Static and deep results are kept per revision in `checks/[site]/[revision]/results.json`. Live results are merged in memory.
