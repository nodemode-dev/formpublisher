# Agents

FormPublisher's engine does every step a person does, so agents drive it the same way: start from a template or import a site, list its routes, preview it, run the checks, build, sign, verify, then prepare a folder for each host and verify it. Claude Code, Codex, Cursor and Antigravity are the four clients `agents install` and `agents status` know.

## The command line

`./formpublisher run` has a command for each step: `status`, `sites`, `import` (a `site-export.zip`, a `.fweb`, a `.fpub` or a publication folder), `import-formweb` (the site open in a running FormWeb, read through its export; `--project ID` takes one of its saved projects), `formweb-projects` (the running FormWeb's saved projects, the open one first), `routes SITE-ID`, `revisions SITE-ID`, `diff SITE-ID` (`--from R`, `--to R`; default the latest against the one before), `check SITE-ID` (`--deep`, `--widths`, `--last`), `preview SITE-ID` (shows a revision on the running engine's local preview host and prints the addresses), `build SITE-ID`, `builds`, `inspect BUILD`, `compare A B`, `reproduce BUILD` (exits 1 when the bytes differ), `fpub BUILD` (`--out FILE`, `--force`: save a build as a `.fpub`), `sign BUILD`, `verify BUILD` (`--allow-unknown`: exit 0 for a valid signature by a key you do not have; without it that exits 1), `keys` (`--create NAME`; `--export ID --to FILE [--force]` and `--import FILE [--name NAME]` write and read an encrypted `.pem` file, asking for a passphrase of at least 8 characters, or reading `FORMPUBLISHER_KEY_PASSPHRASE`), `targets`, `prepare BUILD --target T` (repeat `--target`; `--include-model` keeps FormWeb's model files, which are left out by default), `prepared BUILD`, `verify-prepared BUILD TARGET` (exits 1 when the folder no longer matches), `trash` (`trash restore ENTRY` with `--to PATH` to name the place of an entry whose origin is unknown, `trash delete ENTRY` and `trash empty --yes`), `receive-status`, `templates` and `start TEMPLATE --to FOLDER`. The repository's `docs/mcp-tools.json` lists every command and every MCP tool, generated from the code. `./formpublisher run --help` lists every command and its options. Answers are short text, or JSON with `--json`; failures exit non-zero with the reason in plain words. It uses a running engine with the same data folder, or runs in-process. The desktop app's frozen engine takes the same commands (`formpublisher-engine cli ...`).

## The MCP server

`./formpublisher mcp` serves MCP on stdio. `.mcp.json` registers it for Claude Code in this repository, `.codex/config.toml` for Codex and `.cursor/mcp.json` for Cursor; each runs `node setup/mcp_launch.mjs`, which starts `formpublisher mcp` (or `formpublisher.bat mcp` on Windows), so they work on Windows too. The server follows MCP revision 2026-07-28 (it answers `server/discover`) and still answers the `initialize` handshake for 2024-11-05 to 2025-11-25, with `mcp` 2.3.0. Its tools work over the same routes, and `docs/mcp-tools.json` is the generated list with the counts. Each tool has a class in its `_meta` (`formpublisher/class`): `read` reads only, `data` writes only inside the data folder or the engine's state, and `path` writes to a path the person named (`save_fpub`, and `start_from_template`, which also uses the network). The tools: `list_templates` (read only, the template list the person fetched) and `start_from_template` (a FormWeb project from one, in a folder the person named), and `formpublisher_status`, `list_sites`, `import_site` (an export, a `.fweb`, a `.fpub` or a folder), `list_formweb_projects` (read only), `import_formweb_current` (with `project`, a saved FormWeb project), `receive_status` (read only: FormWeb's Send to FormPublisher inbox and its last receipts), `site_routes`, `list_revisions` and `diff_revisions` (read only: a site's revisions, and the files and routes added, removed and changed between two), `preview_site` (shows a revision on the local preview host and returns its addresses; it opens nothing), `run_checks`, `get_checks`, `build_package`, `list_builds`, `inspect_build` and `compare_builds` (read only: one build's `publish.json` and signature state, and the files changed between two builds), `reproduce_build` (a rebuild in a scratch folder that says whether the bytes match), `save_fpub` (a build as one `.fpub` file at an absolute path; it never replaces a file), `list_keys` (read only: the signing keys and the id to pass on), `sign_build` (marked destructive: it replaces an earlier signature), `verify_build` (read only: `valid`, `known` when the signer's key is one of the person's own, `trusted` when both, `signer`, `message` and, when not valid, `reason`; `valid` with `known` false is a warning to pass on, not a verified package), `list_targets`, `prepare_publish` (with `includeModel`, and `leftOut` in each result; marked destructive: preparing again deletes the target's previous folder), `get_prepared`, `verify_prepared` (checks that a prepared folder still matches its build and keeps the verdict for `get_prepared`), `list_trash` (read only) and `restore_from_trash`, which restores only a recorded or inferred origin and takes `passphrase` for a locked key rebuilt from its `.pem` (the CLI reads it with `trash restore ENTRY --passphrase-stdin`). No tool deletes, restores to a named place, or exports or imports a signing key: removing an entry from the trash for good, `trash restore --to`, `keys --export` and `keys --import` are a person's actions. The server sends the key from `engine.key` with each change, so it works with an engine that is running and needs no key in-process. Reads carry the read-only hint. What an agent does appears in the open window at once through the engine's live events. Preparing writes a folder and never uploads; see [Publishing](Publishing).

## Connect

`./formpublisher agents install` registers the MCP servers and copies the skills for your account in Claude Code, Codex, Cursor and Antigravity (Antigravity gets the MCP servers only; `agents install claude`, `codex`, `cursor` or `antigravity` sets up one; `--dry-run` shows the changes; files are backed up first). `./formpublisher agents status` reports what it found for the four.

An installed app registers its own MCP server: run the engine program inside it with `agents install` (all four clients) or `agents install claude` and so on, then `agents status`. The engine program is `/Applications/FormPublisher.app/Contents/Resources/engine/formpublisher-engine` on macOS, `%LOCALAPPDATA%\FormPublisher\engine\formpublisher-engine.exe` for the default per-user install on Windows, and `/usr/lib/FormPublisher/engine/formpublisher-engine` for the Linux deb or rpm. The MSI installs under Program Files; check the exact folder there. An AppImage cannot be registered by path: extract it once with `--appimage-extract` and run `squashfs-root/usr/lib/FormPublisher/engine/formpublisher-engine agents install`, or use the deb or rpm.

`./formpublisher agents sync` writes `docs/mcp-tools.json`, mirrors `.claude/skills` to `.agents/skills`, checks every tool or command count the documents state against that list, and checks that the shared finder `backend/app/services/agent_lookup.py` still has the bytes whose hash is recorded for its version; `--check` exits 1 on drift or a mismatch. `./formpublisher vendor --check` exits 1 when the vendored FormWeb crates are out of step.

formMCP (`formmcp mcp`) is the family hub that reaches every installed Form app's tools. It is a separate app; when it is missing its entry shows as unavailable and the formpublisher server still works.

## The agent dock

The window has a dock for terminal tabs: View, Agent Dock, `Mod+J` (Cmd or Ctrl+J, changeable in Keyboard Shortcuts), the title bar button or the command palette. It opens at the bottom, and on the right from a window 960 px wide. A shell tab is offered whenever the computer gives the engine a terminal. Claude Code, Codex, Cursor (`cursor-agent`) and Antigravity (`agy`) each get a button when the family's finder (`backend/app/services/agent_lookup.py`) finds the program on this computer, which it can do even when the app was started from the Finder, the Dock or Explorer, and the install line shows for one that is missing. `FORMPUBLISHER_CLAUDE_BIN`, `FORMPUBLISHER_CODEX_BIN`, `FORMPUBLISHER_CURSOR_BIN` and `FORMPUBLISHER_AGY_BIN` point at a program directly. The ask line under the tabs hands a request to Claude Code: it is typed into a Claude Code tab that is running, or starts one.

Each agent tab works in its own folder in the data folder, `agent-tabs/[id]/` (readable only by the person, removed when the tab closes), and reaches FormPublisher's tools through an MCP entry named `formpublisher_tab`, which runs `mcp --tab-key-file` over the file `tab.key` there. An agent started in the dock therefore has the tools with no setup, and the harness skill's rules hold in it as anywhere. The key is made for that tab alone, never appears on a command line, is accepted for the tools like the window's key but refused on the dock's own routes, and ends when the tab's program ends or its tab closes. A plain shell tab gets no key. A tab's environment keeps the person's variables and drops the engine's own `FORMPUBLISHER_` ones, except `FORMPUBLISHER_PORT` and `FORMPUBLISHER_HOME` (and `FORMPUBLISHER_TERMINAL=1`).

The routes are `GET` and `POST /api/terminal`, `POST /api/terminal/{id}/restart`, `/resize` and `/ticket`, `DELETE /api/terminal/{id}`, the stream `WebSocket /api/terminal/{id}/stream?ticket=` (a ticket is bought with the window's key, spent once and good for 60 seconds) and `GET /api/agent-programs`. The dock was checked with stand-in programs only: no real Claude Code, Codex, Cursor or Antigravity has been started from it, and nothing has run on Windows or macOS. The manual's "The agent dock" has the details.

## The skills

- `.claude/skills/formpublisher-harness`: driving FormPublisher through MCP or the command line to import, check, package, sign and prepare sites for a host.
- `.claude/skills/formpublisher-skillset`: changing FormPublisher's own code, where it lives and the laws that hold everywhere.

## The rule agents must keep

FormPublisher only reads FormWeb. An agent never calls FormWeb's `/api/load` and asks the person before importing from a running FormWeb.
