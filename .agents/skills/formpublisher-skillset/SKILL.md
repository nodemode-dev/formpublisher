# formpublisher-skillset

Route every change to FormPublisher's code through this file. It maps where the code lives and states the rules that hold everywhere.

## What the app has now

The window (Home, site tabs, routes strip, inspector, bottom panel, status bar, Preferences), the engine with its command line and MCP server (every tool and command is in `docs/mcp-tools.json`), templates, receiving from FormWeb, revisions, checks, deterministic builds, signing, the `.fpub` format, prepared host folders and the trash. Since 0.7.0 it also has the family's agent dock (terminal tabs for a shell, Claude Code, Codex, Cursor and Antigravity) and the family's finder for those programs, both copied from FormVis.

Design work follows the Form family's look. The reference today is FormVis's `frontend/src/styles/tokens.css`, which FormPublisher's tokens were read against; where the owner uses it, the formai-design-lang skill guides design work, and its scripts are used only when the owner asks for them.

## How the pieces depend

```text
backend/app/services (paths, settings, site intake, the FormWeb reader)
  -> backend/app/routers (one router per file, auto-included)
       -> frontend over /api and the live WebSocket
       -> the command line and MCP server over the same routes
  -> backend/formpublisher_engine.py (PyInstaller entry) -> src-tauri/engine folder
```

## The laws

- **The engine does the work.** Every capability is a route; the window, the command line and the MCP server are surfaces over it. A capability one surface has and another lacks is a bug: add the route, then the command and tool, then the pane.
- **FormWeb is read, never written.** Import zips and folders, and call only a running FormWeb's read-only routes (`/api/export`, `/api/publications`, `/api/releases`, `/api/access`, `/api/projects`, `/api/projects/{id}/file`). Never `/api/load`.
- **The engine stays on loopback.** 127.0.0.1:8280, exact Host check, no other origin drives it.
- **Every change needs the window key.** `WindowKeyGuard` in `backend/app/services/window_key.py` refuses any request that is not GET, HEAD or OPTIONS unless it carries the window key or the engine key (`engine.key`) in `X-FormPublisher-Key`: 403, code `forbidden`. A new write route needs nothing extra, and must not be added to the open list (`OPEN` in that file: the FormWeb receive route and the key claim). A route that changes anything is POST, PUT, PATCH or DELETE, never GET. The window (`frontend/src/window-key.ts`) and the command line's `Client` already send the key; a new caller of the engine does the same. Only the engine's own origin may use the shell's commands (`src-tauri/capabilities/default.json`), and the window's content security policy (`content_policy`) allows only what the window loads: do not widen either to make something work.
- **Signing keys stay in the store.** The private half is reached only in `backend/app/services/keys.py`, and only to create, sign, export, import and remove a key; listing and verify read `keys/index.json`. No MCP tool exports or imports a key. Verify answers through `signer_verdict` (`valid`, `known`, `trusted`, `signer`, `message`); code that reports a signature never reports `valid` alone as trusted.
- **Keys and settings live only in Preferences.** A key is made, imported, exported and removed in the Signing keys panel and the deep check's browser is set in the Checks panel; no sheet or page carries a copy. A sheet that needs one offers a chip or a button that calls `openPreferences(section)` (the Package sheet's Manage keys, the `deep.unavailable` row, the FormWeb unreachable notice).
- **The dock folder and the finder are byte copies.** `frontend/src/dock/` and `backend/app/services/agent_lookup.py` come from FormVis and are never edited here, not even to fix a typo: a change is made in FormVis and copied whole. `python setup/dock_check.py` (against `MANIFEST.json`), `./formpublisher agents sync --check` (against `LOOKUP_HASHES` in `setup/agents.py`) and `npm run typecheck:dock` guard them in CI. Anything the dock needs from FormPublisher goes in `dock-adapter.ts`, `dock-tokens.css` and the engine's own services.
- **An agent tab has its own key, and a plain shell has none.** The key is made for one tab (`window_key.issue_tab`), lives in `tab.key` (0600) in the tab's folder (0700), reaches the program through `--tab-key-file` and never a command line, ends with the tab (`revoke_tab`), and is refused on the dock's own routes: those call `window_key.personal`, and a new route that only a person may use does the same.
- **The suite stays on stand-ins.** The autouse fixture in `backend/tests/conftest.py` gives each test its own home folder, a `PATH` of system folders only (no agent program can be found), its own agent configuration folders and keyring's fail backend; a new test relies on it and never touches the real home, an agent program or a real password store.
- **Checks never start a real agent program.** A test or a check of the dock uses a stand-in program; none of them runs Claude Code, Codex, Cursor or Antigravity.
- **Zero flash.** Every container exists in its final layout before the first paint and is filled in place. Every `z-index` is a layer token from `frontend/src/styles/tokens.css`. Icons are inline `currentColor` SVG; no icon libraries.
- **The family dropdown, never a native select.** Every chooser is `frontend/src/ui/dropdown.ts` (`Dropdown`, `dropdownHtml`): its width is reserved from every option's label before the first paint, and options are patched in place.
- **Accent text uses `--accent-ink`.** Text and icons in the accent colour use `--accent-ink`, which on the light themes is the accent mixed toward black until it reads at 4.5 to 1 (`themes.ts` and the boot script compute it); text on an accent fill uses `--text-on-accent`; fills, rings and lines keep `--accent-color`.
- **Surgical edits.** Hand-made edits, one region at a time; no codemods or scripted text replacement. No emoji, no em dashes in Markdown, no commented-out code, near-zero comments: the reasoning goes in the HASHOUT logs.
- **Read the logs first.** `backend/HASHOUT_LOG.md`, `frontend/HASHOUT_LOG.md`, `src-tauri/HASHOUT_LOG.md` and each module's own `HASHOUT_LOG.md`. Planning documents are in the sidecar, not in this tree.
- **Keep the agents in step.** After changing a command, a tool or a skill, run `./formpublisher agents sync` (it writes `docs/mcp-tools.json` from `backend/app/mcp.py` and `backend/app/cli.py`, mirrors `.claude/skills` to `.agents/skills`, checks the skill files, checks every tool or command count the documents state and checks the finder's recorded hash; `--check` fails on drift). Every new tool gets a class in `TOOL_CLASS` in `backend/app/mcp.py` (`read`, `data` or `path`), or `build()` refuses it. Point at `docs/mcp-tools.json` rather than writing a count; a count that stays must be the generated one. After touching `vendor/formweb-native`, stage it and run `./formpublisher vendor --check`.
- **Versions** are `x.yy.z`, and the release version lives in 17 places, all with the same one: `README.md` (the version badge), `.docs/wiki/Home.md` (Release version), `docs/MANUAL.md` (the two `builtWith` examples), `backend/app/__init__.py`, `frontend/package.json`, `frontend/package-lock.json` (two fields, the top one and the root package's), `frontend/src/version.ts`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` (the formpublisher package), `src-tauri/tauri.conf.json`, the headers of `backend/HASHOUT_LOG.md`, `frontend/HASHOUT_LOG.md` and `src-tauri/HASHOUT_LOG.md` (Current build version), and the `metadata.version` of the two `SKILL.md` files under `.claude/skills`, whose `.agents/skills` mirrors follow with `./formpublisher agents sync`. To find them, `git grep -n` the old version with `-- . ':!CHANGELOG.md'` and leave alone what is not the app's own version: dependency pins that happen to match (`ptyprocess` in `backend/requirements*.txt`, the locks and `NOTICE.md`), and history lines in `docs/MANUAL.md`, the HASHOUT logs and `CHANGELOG.md`.
- **Licences.** FormPublisher is GPL-3.0-only, and every dependency that ships gets a row in `NOTICE.md`. Permissive and GPL-3.0-compatible licences are fine. AGPL is used nowhere. LGPL code only as a separate program, never linked in. Family code from FormVis and FormDeck (Apache-2.0, the same owner) may be taken, with its origin in the HASHOUT log. FormPortal and formcompiler (GPL-3.0-only, another product line) give the look and the data contracts, not code.
- **Locks, toolchains and languages.** Python packages are locked with hashes in `backend/requirements.lock` and `backend/requirements-test.lock`, and installs use `pip install --require-hashes -r backend/requirements.lock`. After changing a requirements file, run `python setup/lock_requirements.py` (uv 0.11.32) and commit the locks; `--check` verifies them. Rust is pinned in `src-tauri/rust-toolchain.toml` and read by `fp_rust_pin` in `setup/lib.sh`; Node is 22.12 or newer. Every interface string is in all 25 locale folders: `python setup/i18n_check.py` must pass. CI runs all three, plus a Windows and a macOS shell check (`cargo check --locked`).
- **Commits** as `nodemode-ai <mackin@nodemode.ai>` only, no trailers of any kind (see `CLAUDE.md`).

## Run it

```bash
./formpublisher_oc_install     # backend venv (from the hashed lock) and interface packages
./formpublisher boot           # engine on 127.0.0.1:8280 and interface on localhost:5280
./formpublisher serve          # the built interface served by the engine on 8280
./formpublisher run status     # the command line
./formpublisher mcp            # the MCP server on stdio
./formpublisher doctor         # toolchain, installs, ports and the vendor row
FORMPUBLISHER_HOME=/tmp/fp ./formpublisher run sites   # a scratch data folder
```
